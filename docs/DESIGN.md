# ATLAS design — the window's visual language

The product is a native window, `rust/atlas-desktop`. This document is the visual language that
window speaks: what a colour may be, what the type scale is, how space works, what can be
clicked, what an empty page says, and the mark the product signs itself with. It is written for
the next person who adds a page or a control, and every rule names the constant or the test that
holds it.

Read it with the code open. The rule is not "the design system says" — it is "this line fails
if you break it":

| Gate | Where it runs | What it stops |
| --- | --- | --- |
| the constant | `src/theme.rs` (`palette!`, `space`, `size`, `role`) | a colour, a size, a gap or a radius invented in a view |
| the self-check | `theme::self_check`, on every debug launch | the same rules, the first time the window opens |
| the unit tests | `theme.rs` `mod tests` (16 `#[test]`s, run with `cargo test --offline -p atlas-desktop --lib`) | a hue, a shadow, an off-ladder role, an unreadable grey |
| the source scan | `tests/disclosure.rs` (`no_label_shouts`, `every_colour_in_the_palette_is_grey`, …) | a label that shouts, a palette that grows a hue, a written file |
| the painted frame | `tests/smoke.rs` | an empty state painted over data, a warning where there is none |

Two habits make the rest of this document checkable. Nothing in a view names a colour: a view
paints with `theme::INK`, `theme::DIM` or `theme::FAINT` and nothing else. Nothing in a view
names a size: a view calls a role (`theme::body`, `theme::dim`, `theme::card_title`,
`theme::page_title`, `theme::number`, `theme::caption`, `theme::section_label`) and a `Painter`
reads `theme::size` when it needs a `FontId`. Where the tree does not keep one of these habits,
§14 says so rather than pretending.

## 1. Colour: grey, and only grey

There is no hue anywhere in the product. Not "we use neutral colours" — grey by construction:
every colour is built with `Color32::from_gray`, which takes one luminance and returns
`r == g == b`, so a hue cannot be typed into the palette even by accident
(`theme.rs` `palette!` macro, and `ALL` is generated by the same macro, so "walk every colour"
cannot miss one).

| Name | Grey | What it is | On page | On panel | On raised |
| --- | --- | --- | --- | --- | --- |
| `PAGE` | 10 | the window behind everything | 1.00 | 1.04 | 1.11 |
| `PANEL` | 16 | a panel, an unfocused field, a recessed card body | 1.04 | 1.00 | 1.07 |
| `RAISED` | 24 | hover, press, a card on a panel | 1.11 | 1.07 | 1.00 |
| `HAIRLINE_SOFT` | 28 | a structural line that is not a boundary (rail edge, row underline) | 1.16 | 1.12 | 1.04 |
| `HAIRLINE` | 36 | the one divider, border and separator | 1.28 | 1.23 | 1.14 |
| `SELECT` | 48 | a selected row's fill (not a highlight colour — the ink talks) | 1.50 | 1.44 | 1.35 |
| `FAINT` | 110 | a boundary that must be seen: the focus-adjacent stroke, a time under a headline | 3.88 | 3.73 | 3.48 |
| `DIM` | 155 | secondary ink that is read: a hint, a caption, a count | 7.12 | 6.85 | 6.39 |
| `INK` | 242 | everything meant to be read | 17.68 | 17.00 | 15.86 |
| `FOCUS` | 255 | the keyboard focus ring | 19.80 | 19.03 | 17.76 |

The ratios are WCAG 2.2 relative luminance against the three surfaces a view can put text on.
`FOCUS` is the crate's own printed measurement: `theme::tests::the_focus_ring_is_visible_on_the_page`
prints `focus ring: 19.80:1 on the page, 2 px` (14 theme tests, run in this checkout on
2026-11-22); the
rest were computed from the same formula `theme.rs::contrast` implements, and that transcription
reproduces the crate's own anchors (white/black `21.00`, focus/page `19.80`) exactly.

What the tests demand of those numbers:

- `INK` and `DIM` clear 4.5:1 on page, panel, raised and select — WCAG AA for text
  (`theme::tests::every_grey_that_carries_text_is_legible`).
- `FAINT` clears 3:1 on the three surfaces, because it is a stroke, not ink (same test).
- `FOCUS` is the brightest value in the palette, brighter than `INK`, and clears 7:1 on the page
  — the house asks more than WCAG's 3:1 for a control boundary, so "focused" can never read as
  "ordinary text" (`the_focus_ring_is_visible_on_the_page`).
- The hierarchy is an ordering, not a taste: focus > ink > dim on the page
  (`tests/disclosure.rs::focus_is_visible_and_body_text_is_readable`).

Three places write a grey outside the palette, each for a reason the file states, and each is
documented where it lives: the graph's own plate (`views/graph.rs` `PLATE = 7`), its node fill
(grey 210) and its relation greys, which are composited from `INK` at an alpha by
`views/graph.rs::edge_grey`; and the icon's plate and ink (`logo.rs` `PLATE = 14`, `INK = 238`).
No view may add a fourth.

A hue would also have to be *painted* to be seen, and that is covered too: `from_gray` protects
the palette, and `tests/disclosure.rs::no_view_introduces_a_hue` reads every `from_rgb` in the
crate and refuses a triple whose three channels are neither the same number nor the same
identifier — so `views/graph.rs`'s `from_rgb(grey, grey, grey)` passes and a `from_rgb(200, 60,
60)` in a painter call fails, in whatever spelling. What no assertion reads is a `Shape` mesh: a
gradient *of greys* is still grey, so it is the "no gradient" rule (§12) that covers it, and that
rule is review.

## 2. Type: one ladder, two faces, seven roles

Five sizes, smallest first, each step a ratio a reader can see:

| Rung | px | Step from the one below | Job |
| --- | --- | --- | --- |
| `size::CAPTION` | 11 | — | the smallest line: a time, a source, a total that supports a headline |
| `size::SMALL` | 12 | ×1.09 | secondary prose: a hint, a note, a status line |
| `size::BODY` | 13 | ×1.08 | running text: a headline in a list, a summary, a button |
| `size::TITLE` | 15 | ×1.15 | a card's title, a number that matters, a section's name |
| `size::PAGE` | 21 | ×1.40 | the page's own title, one per screen |

`theme::LADDER` is the ladder as data, and `theme::tests::the_type_scale_is_one_ladder` asserts
both that it ascends and that every step is between ×1.05 and ×1.6 — so a sixth size cannot be
squeezed in without a visible gap.

The seven roles are the only way text is built (`Role::text`); a role is a size, a face and an
ink:

| Role | Size | Face | Ink | Used for |
| --- | --- | --- | --- | --- |
| `PAGE_TITLE` | 21 | text | `INK` | the page title, one per screen |
| `CARD_TITLE` | 15 | text | `INK` | a card's title |
| `SECTION_LABEL` | 13 | text | `INK` | the name of a group of rows |
| `BODY` | 13 | text | `INK` | running text |
| `SECONDARY` | 12 | text | `DIM` | a hint, an age, a status (called as `theme::dim`) |
| `CAPTION` | 11 | text | `DIM` | a source, a time, a supporting total |
| `NUMBER` | 15 | numeric | `INK` | a count, a weight, an id |

**Two faces, and only the two that ship.** `TEXT_FACE = "Ubuntu-Light"`, `NUMBER_FACE = "Hack"` —
the two epaint bundles. `Weight::face()` is checked against
`egui::FontDefinitions::builtin_font_names()`
(`theme::tests::a_role_is_a_face_that_ships`), so a "bold" that exists only in a stylesheet
cannot be asked for. A number is set in the numeric face because it is then a shape as well as a
word: figures line up down a column.

**No fake weight.** Nothing in the theme sets egui's `strong` flag: in egui 0.37.0 that flag is
read only to pick a colour (`egui-0.37.0/src/widget_text.rs:434`, `strong: _, // already used by
get_text_color`), so setting it next to an explicit colour renders identically and reads as
hierarchy that is not there. `theme::tests::no_role_pretends_to_a_weight_it_does_not_have`
(`theme.rs:989`) scans the shipped half of `theme.rs` for `.strong()` and fails on it. Hierarchy
is size, colour and space. (The rail still sets it in three places — §14.)

**Sentence case, and only sentence case.** The theme never changes a string's case
(`theme::tests::a_label_keeps_the_case_it_is_given`), and the scan in
`tests/disclosure.rs::no_label_shouts` checks every literal that reaches a label call: an
all-capitals literal fails unless it is the product's name, a screaming-snake identifier a
reader has to type (`ATLAS_MODEL_URL`), or a code of three letters or fewer that came from the
archive (`DEU`); and an interior capital fails in any short label, because that is what an
eyebrow is. Prose — more than four words, or holding a full stop — is left alone.

## 3. Space: the 4 px unit

One unit, `space::UNIT = 4.0`, and six named steps plus a column width:

| Name | px | units | Job |
| --- | --- | --- | --- |
| `space::XS` | 4 | 1 | between a label and its value; a control's vertical padding |
| `space::SM` | 8 | 2 | between rows; a control's horizontal padding |
| `space::MD` | 12 | 3 | between two cards; the top of a section |
| `space::LG` | 16 | 4 | between a page's blocks; a card's inner margin |
| `space::XL` | 24 | 6 | between the rail and the page; a control's height |
| `space::XXL` | 32 | 8 | above a page title; a table row's height |
| `space::COLUMN` | 96 | 24 | a field, a slider, a combo box: one form column |

`theme::SPACING` lists every number the installed style carries, and
`theme::tests::the_spacing_scale_is_one_unit` asserts each is a positive whole number of units;
`the_style_carries_the_scale_and_not_a_number_of_its_own` asserts the style carries exactly
those — so a number typed into `styled()` cannot skip the scale. The scale must also ascend, so
a tighter gap can never be named as a looser one. `space::COLUMN × 5` is the width prose is
allowed to take (`views/topics.rs` `table::PROSE_W`, 480 px): an empty state or a detail is read
at about 80 characters, not scanned across a 1400 px window.

The style is on the scale. The views are not all: 12 of their 21 `add_space` calls use a
half-step (§14).

## 4. Form: one radius, two strokes, no depth

- **One corner radius: 2 px.** `theme::RADIUS = 2`, applied to windows, menus, cards, fields and
  every widget state; `theme::tests::nothing_is_rounded_above_two_pixels` walks all seven
  corners egui can round and fails on anything larger. egui 0.37.0's own defaults are 4 px on an
  inactive widget and 6 px on every state that moves — hovered, active, open — and 6 px on
  `window_corner_radius` and `menu_corner_radius` (`egui-0.37.0/src/style.rs:1629`, `:1640`,
  `:1798-1875`), so all seven are lowered. The test also asserts the radius is *not* zero: the
  rule is "at most 2", and a square card is a different design. (`theme.rs`'s own comment above
  `RADIUS` still says "3 px (hovered widgets)"; 3 was egui 0.31's number and the comment did not
  move with the pin. The constant and the test are what hold.)
- **Two stroke weights.** `HAIRLINE_WIDTH = 1.0` for every divider, border and separator
  (`theme::line()`, `theme::soft_line()`), and `FOCUS_WIDTH = 2.0` for the focus ring
  (`theme::focus_stroke()`). A third width is a decision, not a detail.
- **No depth.** `window_shadow` and `popup_shadow` are `Shadow::NONE` — no blur, no spread, no
  offset, alpha 0; `expansion` is 0 in every widget state; the topmost window gets no halo
  (`window_highlight_topmost` off); nothing is striped (`visuals.striped` off).
  `theme::tests::nothing_fakes_depth` asserts every one of those. In egui 0.37.0 the default is
  already `expansion: 0.0` in all ten states (`egui-0.37.0/src/style.rs:1799-1876`), so that part
  is a guarantee kept rather than a library default corrected — a version that started growing
  widgets on hover would be caught by the test, not by eye.
- **No fake bold either.** The same test holds every widget state's text pen at
  `HAIRLINE_WIDTH` (1 px). egui 0.37.0 draws hovered text with a 1.5 px stroke and active text
  with 2 px, which reads as weight the single bundled face does not have; on hover the fill and
  the ink change, the pen does not. This is the same rule as §2's "no fake weight", enforced in
  the style instead of in a role.
- **Recess, not elevation.** A field is `extreme_bg_color = PAGE` — darker than the panel it sits
  on. Nothing is "lifted"; a surface is raised by one grey step and a hairline, never by a shadow.

## 5. Focus, and the keyboard door

**Every interactive thing is reachable and visible from the keyboard.** egui has no focus
visuals of its own: a widget with keyboard focus is styled with `WidgetVisuals::active`, so that
state *is* the focus ring — `FOCUS` at 2 px, the brightest value in the palette
(`theme::widgets()`, asserted by `the_focus_ring_is_visible_on_the_page`).

Painting chooses the ring by how the control is drawn:

| Control | Ring | Where |
| --- | --- | --- |
| buttons, fields, `selectable_label` (the rail, the window chips) | `FOCUS` 2 px, from `WidgetVisuals::active` | `theme.rs::widgets` |
| a table row (Topics, Monitors) | `theme::focus_stroke()`, drawn **inside** the row so the flush rows never paint over a neighbour | `views/topics.rs::table::row` |
| a map dot under hover or selection, and the plate itself | `theme::focus_stroke()` | `views/map.rs::MapView::show` |
| the graph canvas | 1.5 px `INK` — deliberately one step quieter than the palette's ring | `views/graph.rs::GraphView::show` |
| an Overview story row | 1 px `INK`, drawn last and inside the row | `views/overview.rs::story_row` |

That last inconsistency is real and is listed in §14: two canvases paint their own ring instead of
`theme::focus_stroke()`. A new control should use the theme's, not either of those.

"Enter or Space is a click" is egui's own rule, not this crate's: `Response::clicked` returns
true "if the widget had keyboard focus and the user pressed Space/Enter", and it requires the
widget to sense clicks (`egui-0.37.0/src/response.rs:181-190`). A `Label` does not sense clicks —
which is why the Overview's story row is a `Sense::click` allocation rather than a label
(`views/overview.rs::story_row`), and why the rail, the article list and the window chips, all
`selectable_label`s (`Sense::click`), answer the keyboard without any extra code.

The keyboard keys a reader can count on, per control:

| Control | Keys |
| --- | --- |
| rail page, window chip, button | Tab to it, Enter or Space |
| Overview story row | Tab, Enter or Space (it is `Sense::click`, so egui makes both keys a click) |
| Articles list | Tab, Enter or Space (`selectable_label`) |
| Topics / Monitors table | Tab into the table, ↑/↓ to move, Enter or Space to open the row, Esc closes the open row |
| map | Tab into the plate, arrows pan by 8 % of the plate, `+`/`-` zoom, `0` returns to the whole world |
| graph | Tab into the canvas, ←/→ walk the strongest-first order, Esc clears the selection |
| chat composer | Tab into the field, Enter sends, Shift+Enter is a newline, Tab to Send |

## 6. What is clickable, and what a click does

Nothing is decorative-but-clickable, and nothing clickable is only clickable: a pointer action
always has a keyboard answer, and a click never navigates away from the window.

| Where | What a click does | Also |
| --- | --- | --- |
| rail (six labels: Overview, Articles, Graph, Topics, Monitors, Chat) | shows that page, one read of the archive | Enter/Space; the current page is `INK`, the rest `DIM` |
| rail window chips `24 h`, `3 d`, `7 d` | changes the archive window, one read | never re-reads when the window is already that one |
| rail `Refresh` | re-reads even though nothing in the window changed — the archive may have been written by another process | the only request a value cannot express |
| Overview story row | opens that story in Articles | the row is a real widget, not a picture of one |
| Articles list row | selects it; the reading pane on the right fills | a search box filters title and body; `Clear` empties it |
| map dot | selects the place and keeps its label on the plate; clicking the plate clears the selection | hovering shows the same label |
| graph node | selects it; the panel on the right lists its relations, strongest first, each with a reason | drag a node to move it, drag the plate to pan |
| Topics / Monitors row | opens one block under the row: the terms of a topic, the question and cadence of a monitor | the open row takes `SELECT`; the block is on the same fill, so the two read as one |
| chat `Send` | asks the local model, one question at a time, and the answer is a **loop**: up to `tools::MAX_STEPS = 6` steps, each of which may run one of the seven read-only archive tools (`tools::names()`) before the model answers | disabled while a turn is in the air, and while the composer is empty or only spaces. The thinking and the `looking up: …` line are drawn as working, folded to one line once the answer starts, and never substitute for the answer (`atlas-ai/src/chat.rs:241`) |
| a story's source address | copies the address to the clipboard — the window hands nothing to the system's URL opener, so a stored `file:` or custom scheme can never be launched by a click — and only if `src/link.rs` accepts it: `http`/`https` in lower case, a host of 1–253 characters with no `@` and no backslash, printable ASCII only, at most `MAX_LENGTH = 512` characters | the button's words are the host (`Copy example.com`), never a fixed phrase, and the sentence `Copy the source address, then open it in your browser.` sits under it (`views/articles.rs:107-112`). An address that fails the gate is *shown*, as `Source address (not a web address, not offered): …`, so it can still be read and copied by hand and never acted on by accident |
| first screen, `Accept and open ATLAS` | writes one `acceptance` row into `data/requests.db` (`requests::accept_at`, `app.rs:979`); the read that follows asks `accepted_at` again (`:284`) and the workspace is drawn | disabled until the tick below it is set (`gate.ready()`); a failed write keeps the screen up and puts the reason in `CAPTION` under the buttons |
| first screen, `Quit` | closes the window without writing anything (`app.rs:992`) | the only other way out of that screen is the window's own close control |
| first screen, the acceptance tick | the one checkbox in the product: `I have read and accept the Apache License 2.0, the scope in the notice, and the disclaimer above.` | it is a tick, not a button, because the sentence it stands for is longer than a button label may be and a reader should see what they are agreeing to |

Two rules sit behind those rows. **One gesture per target:** on a plate, a press that lands on a
node moves the node and a press on the background pans, and a press is not a pan until the
pointer has travelled past `gesture::SLOP` — so a click that wobbles by a pixel still opens what
it was aimed at. **A read is not a frame:** changing a page, a window or the search box costs one
read of the archive, and a mouse move costs none (`app.rs::needs_read`).

## 7. The map

- The world is **vector, not tiles**: the full 1:50m Natural Earth outlines, parsed once
  (`views/map.rs::World::load`) and simplified *per frame in screen space* — a point is dropped
  when it lands within `SIMPLIFY_PX = 0.45` px of the point kept before it. That is why the coast
  is crisp at every zoom, and `a_coastline_stays_within_a_pixel_of_the_file_at_every_zoom`
  measures it: the drawn coast never departs from the file by more than a pixel.
- A graticule every `GRATICULE_STEP = 30°` in `HAIRLINE_SOFT`, with the equator and the prime
  meridian one shade darker (`HAIRLINE`) so the plate says where zero is without a label.
- One dot per group of places, in `INK`; a dot that stands for several places wears a ring, so a
  cluster never reads as one place. Dots closer than `CLUSTER_PX = 15` px are one dot — the
  anti-blob rule runs on screen distance, so it holds at every zoom.
- Zoom is clamped to `MIN_K = 0.4` … `MAX_K = 400`; a wheel or pinch only *adds* to a pending
  zoom, and one frame spends at most `ZOOM_STEP_MAX` of it — a burst of trackpad events is one
  gesture, not ten (`gesture.rs`, `tests/map_zoom_pan.rs`).
- The label of the pointed-at or picked dot is a `PAGE` box with a hairline and the mark's radius,
  always inside the plate (`label_pos`); each view says what it is in a caption at the plate's
  bottom-left: zoom, places, segments.
- A frame may draw at most `MAX_SEGMENTS = 24 000` segments, longest line first, so a cap thins
  islands and never the continents.

The plate states what it cost, in words, on the card:
`{n} coastlines · {n} points · outlines read in {ms} ms` (`MapView::outlines`). A window that
took a second to read its outlines says so.

## 8. The graph

- Force layout over the relations the archive already holds: repulsion between every pair, a
  spring per relation, cooling. A spring's rest length grows with both node radii
  (`rest_length`), so a hub does not sit on its neighbours, and a collision pass runs after the
  integrator with `CLEARANCE = 1.2` of the two radii — nodes never overlap once settled
  (`nodes_never_overlap_once_the_layout_has_settled`).
- **Strength is weight and brightness, never colour.** A relation line's grey is
  `edge_grey(strength)`: the weakest composites to grey 96 on the plate — 3.2:1, the floor
  `the_weakest_relation_line_is_visible_on_the_plate` proves — the heaviest to grey 176 at 2.8 px,
  still quieter than a node (210) and than ink (242).
- Nodes are grey 210; the hovered node takes a 4 px gap ring in `INK`, the selected one 6 px at
  1.5 px. A press within `HIT_MIN = 12` px of a centre grabs the node: a target at least a
  fingertip wide, whatever the drawn radius.
- Labels are for the strongest nodes only — degree first, then mentions, at most
  `LABELS_MAX = 14` ambient labels plus the selected and hovered one, which are always labelled.
  `place_labels` gives each label one of four sides and *skips* one that would overlap: a graph
  with fewer labels is readable, one with piled-up text is not
  (`labels_are_for_the_strongest_nodes_and_never_overlap`).
- The panel says what connects the selected entity, one row per relation, strongest first, and
  every row carries a reason (`relation_reason`): "named together in 12 stories", or the
  archive's own label when it has one. `every_relation_row_states_a_reason` fails on a row that
  states none.
- The canvas keeps painting only while the layout is moving, and it says so with a caption:
  `{n} entities · {n} relations · {selected or nothing selected}`.

## 9. Tables: Topics and Monitors

One table, not a stack of cards: four columns, a header row that names them and stays put while
the rows scroll under it, one row per topic or monitor, and — for the open row — the detail
underneath. A card per topic repeated four facts that are the same for every row.

- Columns are named in sentence case and set in `CAPTION`/`DIM`; the count column is right-aligned
  so figures read down a column. Column widths are multiples of `space::UNIT`
  (`views/topics.rs::table`).
- A row at rest is the page with a `HAIRLINE_SOFT` underline; hovered it takes `RAISED`; open it
  takes `SELECT` and its detail block sits on the same fill, so the two read as one selection.
- The state column is a dot **and** its word: filled `INK` for "watching", a `DIM` ring for
  "paused" — a state is never a colour only.
- The header and the rows are drawn at the same width, and a scroll-bar gutter
  (`space::MD`) is kept out of the columns, so the bar can never sit on the last cell.

## 10. Empty and error states

**An empty page says what is missing and what to do next.** One sentence, sentence case, ends
with a full stop, at a width a reader can follow (480 px):

| Page | Empty state |
| --- | --- |
| Overview | "Nothing collected in this window carries a coordinate. A story lands on the map once it names a place." |
| Articles | "Nothing matches. Clear the search, widen the window, or collect a story." |
| Topics | `views::topics::EMPTY` — "No topic yet. A topic is what counts as news here: … This window only reads — run a research pass for a topic and it appears here." |
| Monitors | `views::monitors::EMPTY` — "No monitor yet. … This window only reads — save one with atlas-monitor add and it appears here." |
| Chat | "Nothing asked yet. Type a question and press Enter — the local model answers from this machine's archive." |
| Graph | not an empty state but chrome: "Click a node to see what connects it." (and, with a selection, "Nothing connects this entity inside the window.") |

`tests/smoke.rs::each_page_names_its_empty_state_and_a_full_one_paints_none` measures this rather
than trusting it: it draws each page empty, reads the sentence *out of the painted frame*, then
draws the same page with six stories and fails if any part of that sentence arrives — so a page
cannot pretend the archive is empty while it has data, and a page that loses its empty wording
fails instead of quietly making the check vacuous. The topics and monitors sentences are `pub
const`s for exactly that reason: they are a contract, not a caption.

**The window has one warning channel: the status row.** A failure to open the archive, or to read
it, is kept as one sentence and painted there — never over a page
(`tests/smoke.rs::no_page_paints_the_status_rows_failure_sentence` produces the refusal from
`Archive::open` and checks no page paints any part of it). The row's right-hand side says what
the window is (`native window · no browser`), or, on the Chat page, where the model would be. In
the transcript, a failure is a line spoken by "Not answered" — an app note, kept next to the
question it belongs to and never sent to the model, so a failure cannot read as an answer
(`views/chat.rs::ChatState::settle`).

A read that costs less than a millisecond says `<1 ms`, never `0 ms` (`app.rs::millis`): the
window would rather admit the clock's resolution than claim a free query.

**The first screen is a document, not a modal.** `views/license.rs` draws, on a machine where
nothing is set up: a wordmark, the page title `Read this before you start.`, three `DISCLAIMER`
paragraphs at `role::BODY`, a `role::SECTION_LABEL` reading `Apache License 2.0` with the line
`version 2.0, January 2004 — the whole text`, then the whole licence in a bordered column of its
own (`COLUMN = 640.0`) that scrolls while the document around it stays put, then one tick and two
buttons. It is deliberately not a dialog over a blurred workspace, not legalese behind a disabled
button, and not a link to the licence: a link would be a promise this app cannot keep, because it
has no network of its own.
The text arrives through `include_str!` — 201 lines, byte-identical to `LICENSE` in the root
(`cmp` clean), so the screen cannot fail to draw on the day a file is missing. (The module comment
says 176; the file it embeds is 201, and the constant is the one to believe.) The frame
stops before the rail (`app.rs:817`), so a first launch is that page and nothing else, and the
surface behind it is `theme::PAGE`, not a scrim: there is no shadow to cast a modal's depth with
(§12).

**A download in progress is a sentence and a rule, not a spinner.** While `atlas-setup --install`
runs, `src/setup.rs` polls `data/setup.json` every `POLL = 500 ms` and answers one of four things;
the Chat page is where they are drawn (`views/chat.rs::setup_block`). `Setup::Running` is one
`theme::dim` sentence plus `progress_bar`: a `theme::HAIRLINE_WIDTH` rect filled `HAIRLINE_SOFT`,
the arrived fraction filled `DIM`, `CornerRadius::ZERO`, width clamped to 520 px, and no
interaction target at all (`Sense::hover`). `Setup::Failed` gives the reason and `setup::INSTALL_COMMAND`, the command that
tries again, while no question is in flight. The other line — "if the model was never downloaded,
… fetches it once" — is drawn only once a turn has actually failed, because that is this page's
only evidence that the model is not answering. Anything unreadable, empty or unknown is
`Setup::Nothing` and draws nothing: a page may say "I do not know" and may never invent a
percentage, which is the rule that module exists for.

## 11. The mark

`src/logo.rs` is the one place the product signs itself, and the mark is the product's sentence
in one drawing: **a world with a small graph inside it.** The world's outline, one hub at
`(-0.040, 0.020)` of the box, three leaves at three different distances and three different
radii, and three edges that run from the hub to each leaf's rim.

It is deliberately not a globe with a grid on it: a crossed sphere is the icon every map app
already has, and it says nothing about the half of this product that matters, which is that
entities are connected.

- **The hub is the only solid shape** — "the thing that happened" — so the eye lands on it first
  at every size, and the inside of the world is empty of everything else
  (`the_hub_is_solid_and_the_world_inside_it_is_empty`).
- **The leaves are outlines, not dots, once the mark is large enough.** Below `OUTLINE_MIN = 22`
  px a leaf's ring is under a pixel thick and the mark turns to porridge, so the leaves become
  solid circles; the hub is always solid, because it is the subject
  (`the_leaves_are_outlines_at_full_size_and_solid_dots_when_small`,
  `a_small_mark_keeps_the_world_the_hub_and_both_leaves`).
- **An edge stops at the leaf's rim**, not under its centre — `Geometry::rim_toward_hub` is the
  point on the rim nearest the hub — so a line never crosses a node
  (`an_edge_stops_at_the_rim_it_reaches`).
- **Every node sits inside the world it is drawn on**, hub and leaves alike, measured against the
  ring's own radius (`every_node_sits_inside_the_world_it_is_drawn_on`).
- **No text in the mark.** The wordmark is drawn next to it in the rail (`app.rs`: the mark at
  28 px, then `ATLAS`, then `local news graph`); baking letters into a 32 px icon is what makes
  an icon read as mush.
- **Every channel is equal.** The dock icon is rasterised from the same `Geometry`, with 4×4
  supersampling, on a rounded plate (`0.47` of the half-box — the shape a window icon is expected
  to have), and `every_pixel_of_the_icon_is_grey` fails on a single tinted pixel.
- The geometry is expressed twice on purpose — vector for the rail, raster for the window manager
  — and both read `Geometry`, so the two cannot drift by a coordinate. The icon is generated,
  never shipped as a file: a PNG in the tree is one more thing that can go missing. The binary
  hands it to the window manager at 256 px (`main.rs`, `.with_icon(logo::icon(256))`).

The mark is the product's signature, not decoration: it appears once per window, in the rail's
lockup and in the window icon. It is not put on cards, not repeated as a watermark, and not used
as a bullet.


## 12. What this document does not allow

| Not allowed | Because | Enforced by |
| --- | --- | --- |
| any hue — a blue link, an orange warning, a red error, a tinted cursor | the product is monochrome; a colour would carry meaning the words do not | `palette!` → `from_gray`; `theme::tests::the_installed_visuals_carry_no_hue` (egui's dark visuals set blue/orange/red by default, and every one of those fields is assigned); `tests/disclosure.rs::every_colour_in_the_palette_is_grey` and `no_view_introduces_a_hue` |
| gradients | a gradient is decoration pretending to be light | no gradient is a colour here, and every widget fill is one flat `Color32`; a `Painter` mesh is not scanned, so this half is review (§14) |
| glows, halos, "topmost" highlight, striped rows | depth in a flat document is a lie about the surface | `theme::tests::nothing_fakes_depth` (`Shadow::NONE`, `expansion = 0`, `window_highlight_topmost = false`, `striped = false`) |
| shadows, of any kind, including a 1 px lift on hover | same | same test: blur, spread, offset and alpha of both shadow fields |
| rounded corners above 2 px | a 2 px corner reads as "made by a tool"; 6 px reads as a bubble | `nothing_is_rounded_above_two_pixels` |
| an all-capitals label | capitals make a word into decoration read before its neighbours | `tests/disclosure.rs::no_label_shouts` (with the three exceptions: `ATLAS`, a screaming-snake identifier, a ≤3-letter code from the archive) |
| a letter-spaced "eyebrow" above a section | tracking is how an interface shouts without capitals; a group is named by size and space | `theme::tests::a_label_keeps_the_case_it_is_given` (no role adds spacing) + `no_label_shouts` (no interior capital in a short label) |
| numbering that is not a sequence | a decorative "01 / 02 / 03" implies an order that is not there | review: the rail's pages are named, not numbered (`app.rs::tests::the_rail_lists_every_page_once_and_chat_is_one_of_them` asserts each is a one-word sentence-case label); a number on screen is a count from the archive, set in `NUMBER` |
| emoji, or any pictograph in a label | a label is the product; an emoji is a second typeface nobody chose | review — nothing scans for one (§14) |
| a label that names the machine (home directory, environment value, model path) | a label that begins with a home directory tells a passer-by who the reader is | `tests/disclosure.rs` R1–R5, two of them **open** (§14) |
| a second warning channel | two places to say "this failed" is two places to look | `tests/smoke.rs::no_page_paints_the_status_rows_failure_sentence` |

## 14. What this document cannot yet claim

Stated rather than smoothed over, because a design document that hides its exceptions teaches the
next person to copy them.

1. **Three `.strong()` calls survive in `app.rs`** (the `ATLAS` wordmark at `:356`, the selected
   page label at `:362`, the selected window chip at `:384`). In egui 0.37.0 that flag changes no
   weight when a colour is set, which is exactly what `theme.rs`'s own test forbids *inside*
   `theme.rs`; the scan covers the theme, not the frame. Until it moves, the rail's "selected"
   state is ink-and-dot only, and the wordmark is 15 px ink — correct by accident, not by rule.
2. **The wordmark names its size instead of a role**: `RichText::new("ATLAS").size(15.0)` at
   `app.rs:356` rather than `theme::card_title`. 15 is on the ladder, but the number is typed.
3. **Two canvases paint their own focus ring** (`views/graph.rs:713` and `:783`, 1.5 px `INK`;
   `views/overview.rs:224`, 1 px `INK`) instead of `theme::focus_stroke()` (2 px `FOCUS`). A new
   control should copy the theme's, not theirs.
4. **Type is typed rather than called, in four places**: `views/overview.rs:153-154`
   (`13.0`/`12.0` — the values of `BODY`/`SMALL`), `views/graph.rs:570` (`10.5` px, off the
   ladder) and `app.rs:356` (above). The map and the tables do it correctly, through
   `theme::size` and `theme::Weight`.
5. **Twelve of the views' twenty-one `add_space` calls are half-steps** — `2.0` (3), `6.0` (4),
   `10.0` (4), `14.0` (1); the twenty-first passes `space::SM` (`views/topics.rs:326`) and is on
   the scale. The rail's frame margins are still `(12, 14)` and `(12, 6)` (`app.rs:347`, `:482`)
   and the page's is `(20, 16)` (`:490`). The *style* is on the 4 px scale and a test proves it;
   the views are not, and no test reads them. (Counted with
   `grep -o "add_space([0-9.]*)" rust/atlas-desktop/src/views/*.rs | sort | uniq -c`.)
6. **`views/mod.rs`'s card hard-codes `CornerRadius::same(2)`** instead of `theme::RADIUS`.
   Equal today, free to drift.
7. **No test reads a `Shape` mesh, an emoji, or a decorative numeral.** A hue cannot be typed
   (`from_gray`) and a view's own `from_rgb` is caught by `no_view_introduces_a_hue`, but a
   *gradient of greys* is still grey to that scan, an emoji in a `Shape::text` is just glyphs,
   and a hand-drawn "01" is just two characters. Those three are review rules.
8. **The two disclosure rules that were open are closed.** They used

   `no_label_spells_out_where_the_model_lives` — failed in that same run and is not mine to

    reader's keyboard start where they clicked.

    so it carries `#[allow(dead_code)]`. The first page that needs a group name should call it
    rather than write a capitalised label by hand — which is the whole reason it exists.

## 15. A checklist for a new page

1. A heading: `heading(ui, "Page", "one sentence that says what this page is.")`.
2. Text only through a role: `theme::body`, `theme::dim`, `theme::card_title`, `theme::number`,
   `theme::caption`, `theme::section_label`, `theme::page_title`.
3. Any number a reader sees: `views::nf` (thin spaces), in `theme::number` or the numeric face.
4. Any date: `views::when` (a time today, `20 Nov` otherwise).
5. Any grouping: `card(ui, "Title", "a note", |ui| …)` — a hairline box on `PANEL`, 12 px inside.
6. Any list of rows: the table in `views/topics.rs::table` (header, row states, Enter/Space,
   arrows, the open row's detail, the caption under it).
7. An empty state: one sentence, says what to do next, and add it to the smoke test's list.
8. Anything clickable: a real widget (`Sense::click`, `selectable_label`, `Button`), a keyboard
   answer, and a pointer cursor on hover.
9. Before you commit: `cargo test --offline -p atlas-desktop --lib` for the theme, and
   `cargo test --offline -p atlas-desktop --test disclosure --test smoke` for the labels and the
   frames. Nothing in this document is a matter of taste that a reviewer has to remember.
